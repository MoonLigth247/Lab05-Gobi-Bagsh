## Newman үр дүн

| Ажиллуулалт | Requests | Assertions executed | Assertions failed | Exit code |
|---|---|---|---|---|
| PASS | 24 | 34 | 0 | 0 |
| FAIL | 24 | 34 | 1 | 1 |
| DOWN | 24 | 34 | 34 | 1 |

- `results/newman-pass.txt` — бүгд PASS, exit 0
- `results/newman-fail.txt` — зориуд буруу oracle (1 assertion), exit 1
- `results/newman-down.txt` — сервер унтарсан, ECONNREFUSED, exit 1

**Интерфейсийн vs oracle-ийн алдаа:** DOWN нь холболтгүй (интерфейсийн алдаа) — сервер ажиллахгүй байгаа тул HTTP хүсэлт огт явагдахгүй, ECONNREFUSED буцаана. FAIL нь сервер ажиллаж байгаа ч oracle буруу (тестийн алдаа) — сервер хариу буцаасан, гэхдээ хүлээгдэх утгатай тохирохгүй.

## Дүгнэлт

Энэ лабораторид API системийн тестийг Postman болон Newman ашиглан бүрэн хэрэгжүүлсэн. Лекц 5-ын 5 алхмыг дагаж, тестлэгдэх функцийг тодорхойлж, сонголт ба төлөөлөх утгуудыг гаргаж, спецификаци боловсруулж, 10 тест кейс бичсэн. Хамгийн их бодол шаардсан хэсэг нь эквивалент ангийн хил хязгаарыг тодорхойлох байсан — ялангуяа оюутан байхгүй, хичээл байхгүй, урьдач нөхцөл дутуу гэх мэт олон төрлийн алдааг ялгах. Боломжгүй хослол гэж оюутан байхгүй + хичээл байхгүй хослолыг туршиж үзсэн бөгөөд сервер эхлээд оюутныг шалгадаг тул ERROR_NO_STUDENT буцаадаг болохыг тогтоосон. Тестүүд нь серверийн семантик (201 = амжилт, 200 + ERROR_* = оролтын алдаа, 400 = формат буруу) зөв эсэхийг баталсан бөгөөд ямар нэгэн ноцтой согог илрээгүй. Newman-ы PASS ажиллуулалт 34 assertion бүгд амжилттай болсныг, FAIL нь 1 assertion буруу oracle-тойгоор exit 1 буцаасныг, DOWN нь сервергүй үед ECONNREFUSED алдаа гаргасныг харуулсан. Энэ нь CI/CD-д quality gate хэрхэн ажиллахыг харуулж байна — exit code 0 нь deploy хийх боломжтой, exit 1 нь блоклох ёстой гэсэн үг.
